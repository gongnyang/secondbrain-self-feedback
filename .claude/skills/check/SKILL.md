# 자가 점검

- 맡는 역할: 평가 에이전트
- 입력: `$ARGUMENTS` (보고서 파일 경로). 없으면 경로를 묻는다

## 읽는 것

- `brain/rubric.md`: 공통 점검표
- `brain/criteria/`: `status: 승인`인 기준만 판정에 쓴다. `가설`은 리포트에 "참고"로만 싣는다
- `brain/exemplars/`: 같은 보고유형의 사례 3건까지
- `ontology/term/`, `ontology/format/`, `ontology/rule/`: 용어와 표기 점검용
- 로그 원본(`loop/logs/`)은 읽지 않는다

## 절차

1. 보고서를 읽고 보고유형을 정한다
2. 점검표의 축마다 이유를 먼저 적고, 그다음 등급(통과 / 보완 / 재작성)을 매긴다
3. 지적마다 보고서 원문 인용과 기준 id(또는 점검표 축 번호)를 붙인다. 둘 중 하나라도 없으면 그 지적은 버린다
4. 고칠 것은 영향이 큰 순서로 3건까지 고른다. 건마다 수정 예시를 한 문장으로 적는다
5. `brain/rubric.md`의 판정 규칙으로 전체 판정을 낸다
6. `reports/_template.html`을 복사해 자리표시(`{{ }}`)를 채우고 `reports/YYYY-MM-DD_제목.html`로 저장한다
7. `loop/logs/YYYY-MM-DD_제목.md`를 만들고 `## 사전 평가` 아래에 판정, 축별 등급, 지적 목록, 쓴 기준 버전을 적는다

## 하지 않는 것

- 기준 파일을 고치지 않는다. 기준이 이상해 보이면 로그에 한 줄 남긴다
- 보고서를 대신 쓰지 않는다. 수정 예시는 문장 단위까지만 든다
- 작성자의 자기평가나 사정을 판정에 넣지 않는다
- 근거 없이 칭찬하거나, 채울 것이 없는데 지적 3건을 억지로 채우지 않는다

## 끝나면

- 리포트 경로와 판정 한 줄만 알린다
- 승인된 기준이 하나도 없으면 "공통 점검표만으로 본 결과"라고 리포트 맨 위 판정 줄에 적는다
