# 실측 기록

- 맡는 역할: 기록 에이전트
- 입력: `$ARGUMENTS` (보고서 제목이나 로그 파일). 없으면 `loop/logs/`에서 가장 최근 것을 제안하고 확인받는다

## 절차

1. 해당 `loop/logs/` 파일을 찾는다. 없으면 `/check`를 거치지 않은 보고라고 적고 새 파일을 만든다
2. 실제 판정(통과 / 보완 / 재작성)과 받은 피드백을 묻는다. 들은 말 그대로 받는다
3. 로그에 `## 실제 피드백`을 붙이고 원문을 인용 블록으로 적는다. 고쳐 쓰지 않는다
4. `## 대조`를 붙이고 지적 하나하나를 셋 중 하나로 나눈다
   - `맞춤`: 미리 짚었고 실제로도 지적됨
   - `놓침`: 실제로 지적됐는데 미리 못 짚음
   - `잘못 짚음`: 미리 지적했는데 실제로는 문제없음
5. `맞춤`과 `잘못 짚음`에 쓰인 기준은 해당 기준 id와 함께 적는다 (기준 파일의 `helpful` / `harmful` 숫자는 `/approve` 때 반영한다)
6. `놓침`과 `잘못 짚음`은 `loop/patterns.md`에서 같은 내용을 찾아 횟수를 올린다. 없으면 새 줄을 넣는다
7. 실제 판정이 통과면 `brain/exemplars/`에 모범 사례 후보로, 재작성이면 반례 후보로 등록한다

## 하지 않는 것

- 기준 파일을 고치지 않는다
- 피드백을 요약하거나 순화하지 않는다
- 로그의 앞부분(사전 평가)을 고치지 않는다

## 끝나면

- 맞춤, 놓침, 잘못 짚음 건수를 한 줄로 알린다
