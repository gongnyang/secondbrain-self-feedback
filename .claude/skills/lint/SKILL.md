# 점검

- 고치지 않고 찾기만 한다. 결과는 목록으로 낸다

## 보는 것

1. **참조**: `brain/`과 `ontology/`에서 쓰인 id가 실제로 있는가. 없는 id, `deprecated`인 id
2. **필수 필드**: `ontology/_schema.md`와 `brain/criteria/_template.md`의 필드가 빠진 항목
3. **인덱스**: `ontology/index.md`, `brain/index.md`와 실제 파일이 맞는가. 인덱스에 없는 파일, 파일 없는 인덱스 줄
4. **용어**: 정식어가 아닌 동의어, 금지어가 쓰인 곳
5. **근거**: `status: 승인`인데 원문 인용이 없는 기준, `sources`가 빈 온톨로지 항목
6. **중복**: 제목이나 정의가 거의 같은 항목
7. **노후**: `harmful`이 `helpful`보다 큰 기준, 90일 넘게 쓰이지 않은 기준
8. **잠금**: `loop/approvals/OPEN`이 남아 있는가
9. **분량**: `CLAUDE.md`가 200줄을 넘는가

## 끝나면

- 종류별 건수와 파일 경로를 목록으로 낸다
- 고칠 수 있는 것(인덱스, 필드 누락)과 승인이 필요한 것(기준 관련)을 나눠 적는다
- 기준 관련 항목은 `/propose`로 넘기라고 안내한다
