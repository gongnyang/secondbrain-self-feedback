02 · 노선 하나

실행선: 보고서 한 건을 고친다

직원은 초안을 넣고 명령을 한 번 실행한다. 시스템은 사전 점검까지만 한다.

    맡는 쪽

02 · 노선 둘

학습선: 기준 자체를 고친다

실제 보고에서 받은 피드백을 사전 평가와 나란히 적는다. 한 번 나온 차이로는 아무것도 바꾸지 않는다.

학습 루프

  1. 4

    1차 보고

    환승 · 실행선에서

    실제 피드백이 학습선으로 넘어간다

  2. 5

    실측 기록

    실제 피드백과 사전 평가를 대조한다

    들어가는 것
    실제 피드백
    →
    나오는 것
    사전 평가와 나란히 적은 대조 기록
    맡는 쪽
    기록 에이전트
    명령
    /record

    시스템이 놓친 것과 잘못 짚은 것이 여기서 드러난다.

  3. 6

    패턴 축적

    반복되는 차이를 모은다

    들어가는 것
    대조 기록
    →
    나오는 것
    반복되는 차이와 횟수
    맡는 쪽
    분석 에이전트
    명령
    /propose

    서로 다른 보고에서 같은 차이가 반복될 때만 패턴으로 올린다.

  4. 7

    기준 제안

    근거를 붙여 변경안을 올린다

    들어가는 것
    패턴
    →
    나오는 것
    변경안 카드(바꿀 내용, 근거 사례, 영향)
    맡는 쪽
    제안 에이전트
    명령
    /propose

    근거 로그 링크가 없으면 올리지 않는다.

  5. 8

    최종 승인

    주 1회, 승인한 것만 기준이 된다

    들어가는 것
    변경안 카드
    →
    나오는 것
    기준 새 버전, 반려 기록
    맡는 쪽
    승인권자
    명령
    /approve

    기준을 바꾸는 문은 이것 하나다.

  6. 세컨드브레인

    기준 v+1

    평가기준 · 내부기준

    버전을 올리고 이전 버전은 남겨 둔다. 2 자가 평가는 이 기준을 읽는다.

에이전트는 기준 파일을 읽기만 한다. 기준 파일에 쓰는 것은 8번뿐이다.

03 · 환승역

두 고리는 1차 보고에서 만나고, 세컨드브레인에서 다시 만난다

환승역 하나 · 실행선 → 학습선

4 1차 보고

  • 실행선의 마지막 역이자 학습선의 첫 역이다.
  • 고친 보고서로 보고하고, 받은 실제 피드백이 학습선으로 넘어간다.
  • 보고와 판정은 사람이 한다. 시스템은 사전 점검까지만 한다.
환승역 둘 · 학습선 → 실행선

세컨드브레인

  • 학습선이 돌아오는 역이자 2 자가 평가에 기준을 대는 역이다.
  • 승인된 변경안만 기준 v+1이 된다.
  • 이전 버전은 남겨 두어 언제든 되돌릴 수 있다.
04 · 전 구간 적용

경량 온톨로지: 모든 에이전트가 따르는 용어와 표기의 약속

경량 온톨로지 전 구간 적용

무엇이 있고 어떻게 부르는지만 정한다.무엇이 좋은지는 세컨드브레인이 정한다.

비즈니스 인텔리전스2

  • 지표정의, 산식, 단위, 집계 주기예: 매출총이익률
  • 사업 대상지표가 재는 대상예: 고객, 프로젝트

공통2

  • 용어정식 명칭과 동의어정식어는 하나, 나머지는 대체어 또는 금지어
  • 규칙금지어, 필수 표기예: 흰 바탕의 작은 오렌지 글씨는 #D04000

브랜드 아이덴티티3

  • 표기단위, 소수점, 통화 표기예: 억 원 단위, 소수 첫째 자리
  • 톤문체 규칙과 좋은 예, 나쁜 예예: 보고서 문체, 대외 문체
  • 시각 토큰색, 서체예: 키컬러 #FF5000
  • 타입은 일곱 개, 늘리지 않는다.새 타입이 필요해 보이면 만들지 않고 변경안으로 올린다.
  • 두 축은 두 곳에서 만난다.지표와 표기, 용어와 규칙. 같은 숫자는 항상 같은 단위로, 정식어는 하나만 쓴다.
  • 값 판단은 넣지 않는다."얼마 이상이어야 좋다"는 온톨로지가 아니라 세컨드브레인에 적는다.
05 · 누적

쌓이는 길은 하나, 문도 하나

시스템은 스스로 쌓지만, 기준을 스스로 바꾸지는 못한다.

  1. 로그평가와 실제 피드백을 그대로 적는다. 지우지 않는다
  2. 패턴서로 다른 보고에서 같은 차이가 반복될 때만 올린다
  3. 제안바꿀 내용 한 줄, 근거 사례, 바꿨을 때의 영향
  4. 승인주 1회 묶어서 승인, 반려, 보류
  5. 기준버전을 올리고 이전 버전은 남겨 둔다

자동

대상
보고서 사례, 평가 로그, 대조 기록, 패턴 횟수
방식
명령을 돌릴 때마다 기록

사후 확인

대상
용어 추가, 모범 사례 등록
방식
먼저 반영하고 주간 목록으로 확인

사전 승인

대상
기준 문구, 가중치, 문턱값
방식
변경안 카드로 올리고 승인된 것만 반영
06 · 지표와 명령

돌릴수록 좋아지는지 보는 지표

판정 일치율

사전 판정과 실제 판정이 같았던 비율

사전 포착률

실제로 지적된 것 중 미리 짚은 비율

1차 보고 통과율

재작성 없이 넘어간 비율

제안 채택률

올린 변경안 중 승인된 비율

목표 수치는 도입 전 지금 수준을 먼저 잰 뒤에 정한다.

명령 여섯 개

직원

  • /check초안을 점검하고 1장 리포트를 만든다
  • /record실제로 받은 피드백을 적는다

관리자

  • /ingest인터뷰와 문서를 읽어 위키와 기준 초안을 만든다
  • /propose반복되는 차이를 모아 변경안을 만든다
  • /lint끊어진 링크, 미등록 용어, 낡은 페이지를 찾는다

승인권자

  • /approve변경안을 승인하거나 반려하고 버전을 올린다

직원이 쓰는 명령은 두 개뿐이다.
