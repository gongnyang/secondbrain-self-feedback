# 승인 게이트

- 목적: 시스템이 스스로 쌓되, 임원 기준은 임원만 바꾼다
- 근거 논문 1건 외에는 (제안)

## 왜 필요한가
- 사람은 결과물을 채점하면서 기준을 정의하게 된다(criteria drift). 기준을 처음부터 완전히 적을 수 없다
- 따라서 기준이 계속 수정될 것을 전제로 설계해야 한다
- 출처: EvalGen https://arxiv.org/abs/2404.12272

## 설계 (제안)
- **쓰기 권한 분리**: 큐레이터 에이전트는 기준 파일을 못 고침. 제안 파일만 만들 수 있음
- **제안 카드 형식**: 변경 내용 1줄 + 근거 사례 2~3개 + 예상 영향(재평가 결과) + 승인/반려/보류
- **주간 묶음 승인**: 상위 5건 이내, 5분 안에 끝나게. 임원 실제 피드백과 직접 연결된 건을 먼저 배치. 효과 수치는 미확인
- **위험 등급 분리**
  - 용어·사례 추가: 사후 일괄 확인
  - 기준 문구·가중치 변경: 사전 승인
- **롤백**: 버전마다 스냅샷. 승인 후 일치율이 떨어지면 되돌리기를 제안
