# 수집(intake) 구조

- 임원 PC 안에서 인터뷰·문서·피드백을 자동으로 모으는 구조. 대부분 (제안)

## 폴더
- `00_inbox/{interview,docs,mail,feedback}`: 들어오는 곳
- `10_raw`: 원본 + 해시 보관
- `20_text`: 변환본
- `30_masked`: 마스킹본
- `40_extracted`: 후보 기준
- `90_quarantine`: 기밀 의심

## 인터뷰 데이터가 inbox에 모이게 하는 법
- 녹음·전사 앱의 저장 경로를 `00_inbox/interview`로 고정
- 파일 감시 → 이동 후 원위치에 바로가기 남김

## 파일 유형별 변환
- docx / pptx / pdf → markdown: MarkItDown, Docling 등 (이번 조사에서 미확인)
- pptx는 슬라이드 노트와 코멘트를 따로 추출
- 음성 → 로컬 Whisper 전사 (미확인)

## 메타데이터
- 원경로, SHA-256, 작성일, 작성자, 유형, 관련 보고서 id, 민감도 등급

## 중복 제거
- 해시로 완전 중복 제거
- 버전 파일은 최신본만 추출 대상

## 개인정보·기밀
- 처리는 전부 로컬
- 화이트리스트 폴더만 수집 (최소 수집)
- Presidio로 마스킹. 기본은 영어라 한국어 인식기 추가 필요. 주민번호 인식기 존재 여부는 출처끼리 엇갈림 https://microsoft.github.io/presidio/analyzer/languages , https://microsoft.github.io/presidio/supported_entities
- 메일은 임원 피드백 문장만 발췌

## 열린 문제
- 이 번호형 폴더안과 [[폴더-구조-권고안]]의 `raw/ inbox/ proposals/`를 하나로 합쳐야 함
