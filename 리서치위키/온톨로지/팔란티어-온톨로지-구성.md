# 팔란티어 온톨로지 구성

- 공식 문서 기준. "dynamic layer"만 미확인

## 구성 요소

| 요소 | 뜻 |
|---|---|
| Object Type | 실제 엔티티·이벤트의 스키마. Object는 그 인스턴스 |
| Property | 오브젝트 특성의 스키마. Shared Property는 여러 타입에서 재사용 |
| Link Type | 두 오브젝트 타입 사이 관계의 스키마 |
| Action Type | 오브젝트·속성·링크 변경을 묶어 한 번에 적용하는 트랜잭션 + 부수효과(알림, 웹훅). 제출 조건(권한, 검증) 설정 가능 |
| Function | 오브젝트를 입력받아 결과를 내는 코드 로직 |
| Interface | 공통 형태를 정의하는 다형성 타입 |

- 출처: https://www.palantir.com/docs/foundry/ontology/core-concepts/ , https://www.palantir.com/docs/foundry/action-types/overview/

## 레이어
- 공식 문구: semantic elements (objects, properties, links) / kinetic elements (actions, functions, dynamic security)
- 출처: https://www.palantir.com/docs/foundry/ontology/overview/
- "dynamic layer" 정의는 공식 문서에서 미확인. 2차 자료끼리도 설명이 갈림 https://tiro.ooo/en/blog/ontology-structure-for-decisions

## Writeback (결정이 데이터로 되돌아가는 구조)
- 사용자 결정·인사이트가 온톨로지 편집으로 쌓이고, 타입별 writeback dataset에 저장됨
- 액션은 외부 시스템에도 되돌려 씀
- 2022 백서: 결정을 lineage와 감사 추적까지 포함해 원천 시스템에 되돌리고, 지속 학습으로 연결
- 출처: https://palantir.com/docs/foundry/ontology/why-ontology/ , https://palantir.com/assets/xrfr7uokpv1b/4mSNoWcwpgo5G8lRmBSnbk/2d33af8f6c717377197aae56d683f82d/Connecting_AI___Machine_Learning_with_Operations.pdf
- 이 프로젝트의 누적 루프와 같은 구조 → [[7단계-루프-초안]]

## AIP에서 LLM이 온톨로지를 쓰는 방식
- 도구는 data / logic / action 세 범주
- LLM은 도구를 요청만 하고, 실행은 플랫폼이 사용자 권한으로 함
- 에이전트 도구: Action(자동 실행 또는 사용자 확인 후 실행), Function, Object query, Command, Request clarification
- 출처: https://palantir.com/docs/foundry/agent-studio/tools
- 블로그 글은 미러본으로 확인 https://hn.jakechampion.name/reader/https://blog.palantir.com/building-with-palantir-aip-data-tools-for-rag-oag-b3b509c8b0f3
- "확인 후 실행"이 [[승인-게이트]]의 선례
