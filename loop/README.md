# 누적 루프

- 길은 하나: 로그 → 패턴 → 제안 → 승인 → 기준

| 단계 | 위치 | 누가 쓰나 | 규칙 |
|---|---|---|---|
| 로그 | `logs/` | `/check`, `/record` | 추가만. 지우지 않는다 |
| 패턴 | `patterns.md` | `/record`, `/propose` | 같은 차이가 나올 때마다 횟수를 올린다 |
| 제안 | `proposals/` | `/propose`, `/ingest` | 근거 로그 링크가 없으면 올리지 않는다 |
| 승인 | `approvals/` | `/approve` | 승인, 반려, 보류를 날짜와 함께 남긴다 |
| 기준 | `../brain/criteria/` | `/approve` | 항목 단위로 고치고 버전을 올린다 |

## 문턱 (초기값, 운영하며 조정)

- 패턴 → 제안: 같은 차이 3회 이상, 서로 다른 보고 2건 이상
- 주간 승인 묶음: 5건 이내, 실제 피드백과 직접 이어진 것부터
- 승인 없이 반영하는 것: 용어 추가, 사례 등록 (주간 목록으로 사후 확인)
- 승인이 필요한 것: 기준 문구, 가중치, 문턱값

## 지표 (`metrics.md`에 달마다 적는다)

- 판정 일치율: 사전 판정과 실제 판정이 같았던 비율
- 사전 포착률: 실제로 지적된 것 중 미리 짚은 비율
- 1차 보고 통과율: 재작성 없이 넘어간 비율
- 제안 채택률: 올린 변경안 중 승인된 비율

## 로그 파일

- 파일명: `logs/YYYY-MM-DD_제목.md`. 보고서 한 건에 파일 하나
- `## 사전 평가` (`/check`가 씀)와 `## 실제 피드백`, `## 대조` (`/record`가 씀)를 차례로 붙인다
