# 세컨드브레인 자가피드백 시스템

- 1차 보고 전에 직원이 보고서를 스스로 점검하게 하는 시스템
- 기준을 한 번 주면, 보고가 돌 때마다 기록이 쌓이고 기준이 정교해진다
- 지금 상태: 뼈대. 인터뷰와 기준 데이터는 아직 없다

## 그림

- [site/index.html](site/index.html): 시각화 사이트. 노선도 스타일, 큰 화면 발표용
- [배선도-D.html](배선도-D.html): 노선도형
- [배선도-B.html](배선도-B.html): 블루프린트형
- [디자인플랜.html](디자인플랜.html): 설계 요약, 지점별 설명 스크립트, 예상 질문
- [시안/](시안/): 스타일 시안 5종
- [리서치위키/index.md](리서치위키/index.md): 조사 자료 42쪽

## 구조

```
CLAUDE.md            전역규칙 (경량 온톨로지 요약)
ontology/            경량 온톨로지: 용어, 지표, 사업 대상, 표기, 톤, 시각 토큰, 규칙
brain/               세컨드브레인: 원본 기준, 승인된 기준, 점검표, 사례
intake/              수집: 인터뷰, 문서, 피드백 원자료
loop/                누적: 로그, 패턴, 변경안, 승인 기록
reports/             1장 점검 리포트
.claude/skills/      명령 6개
.claude/hooks/       기준 파일 보호 장치
```

## 명령

| 명령 | 쓰는 사람 | 하는 일 |
|---|---|---|
| `/check <보고서>` | 직원 | 초안을 점검하고 1장 리포트를 만든다 |
| `/record` | 직원 | 실제로 받은 피드백을 적는다 |
| `/ingest` | 관리자 | 인터뷰와 문서를 읽어 위키와 기준 초안을 만든다 |
| `/propose` | 관리자 | 반복되는 차이를 모아 변경안을 만든다 |
| `/approve` | 승인권자 | 변경안을 승인하거나 반려하고 버전을 올린다 |
| `/lint` | 관리자 | 끊어진 참조, 미등록 용어, 낡은 페이지를 찾는다 |

## 처음 돌리는 순서

1. `intake/sources.md`에 읽어도 되는 폴더를 적는다
2. 인터뷰 파일을 `intake/inbox/interview/`에 넣는다 (또는 녹음·전사 저장 경로를 이 폴더로 잡는다)
3. `/ingest` → 온톨로지 초안과 기준 후보가 생긴다
4. `/approve` → 확인한 것만 `brain/criteria/`에 들어간다. 처음 승인본은 `brain/anchor/`에도 보관한다
5. 직원이 `/check`와 `/record`를 쓰기 시작한다
6. 주 1회 `/propose` → `/approve`

## 알아둘 것

- **자료 전송**: 파일은 이 PC 안에 있지만, 점검과 정리에 쓰는 AI 호출은 외부 서버를 거친다. 사내 보안 정책에 맞는 경로를 먼저 확인한다
- **올리지 않는 것**: `intake/`의 원자료, `loop/logs/`, `reports/`의 실제 리포트는 `.gitignore`로 빠져 있다. `brain/`과 `ontology/`는 올라간다. 기준 내용까지 저장소에 두기 싫으면 `.gitignore`에 추가한다
- **보호 장치의 한계**: `.claude/hooks/protect-criteria.ps1`은 파일 쓰기 도구로 기준 파일을 고치는 것을 막는다. 셸 명령으로 고치는 것까지는 막지 못한다
- **판정 대체 아님**: 리포트는 사전 점검이다. 실제 판정과의 일치율을 재서 믿을 만한지 확인한다
- 점검표, 타입, 문턱값은 조사를 토대로 만든 초안이다. 인터뷰가 들어오면 바뀐다
